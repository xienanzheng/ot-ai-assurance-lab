# Modular V2 local bench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build an independent local water bench with typed process packages, OPC UA capture, gated simulated commands, durable records and delayed feedback, then prove reuse with simulated cooling.

**Architecture:** A controller owns the process and command receiver. A separate supervisor captures OPC UA data, calls configured providers and journals decisions in PostgreSQL. The React UI observes the supervisor; it does not own scheduling. No external physical writer is supplied.

**Tech Stack:** Python 3.12+, Pydantic, FastAPI, asyncua, SQLAlchemy/PostgreSQL, React/Vite, Docker Compose. SQLite is restricted to fast isolated unit tests.

**Spec:** ../specs/2026-10-24-local-ot-integration-testing-design.md and ../specs/2026-10-24-physical-pilot-architecture-design.md

## Global Constraints

- Root: sibling `water-ot-ai-lab-v2`, independent local Git repository; no public remote.
- No imports, symlinks, volumes, credentials or runtime control dependencies from V1.
- Compose project `water-ot-ai-lab-v2`; host ports `127.0.0.1:18790` and optional `127.0.0.1:18840` only.
- External acquisition is read-only. The command adapter accepts only the bundled simulator receiver, not browser-selected endpoints.
- Audit modes off/observe/required. Required timeout, flag or malformed review blocks application.
- Restart resumes observation, disarms control and invalidates old generation requests; unresolved outcomes block new requests.
- First endurance budget: 60 wall minutes and at most 12 decision calls; time-accelerated tests reported separately.
- User's proceed authorises implementation; execute natively and obtain one independent code review. Site hardware/PLC-specific writes, cloud deployment and training remain outside scope.

## Review Focus

- Process package changes during inference: bind profile/generation/ownership and recheck at acceptance (tasks 2, 4).
- Finite numbers, units and future timestamps: reject before eligibility (tasks 1, 3).
- Database failure between request and acknowledgement: preserve unknown state and do not replay (tasks 2, 4).
- Browser closure and concurrent requests: one server-side owner; scheduling independent of UI (tasks 4, 5).
- Provider unavailability: preserve an inference failure and continue telemetry; never disguise fixtures as Qwen (tasks 4, 6).
